# 메모리 매핑 파일(Memory-Mapped File)

- 파일의 일부 또는 전체를 프로세스의 가상 메모리 주소 공간에 연결해 배열처럼 접근한다.
- 일반적인 `read/write`보다 복사와 시스템 콜을 줄일 수 있어 대용량 파일, 랜덤 접근에 유리하다.
- 실제 데이터는 페이지 폴트 시 로드되므로 성능과 안정성을 위해 페이지 크기, 동기화, 파일 수명을 고려해야 한다.

## 개념 설명

메모리 매핑 파일은 파일과 프로세스의 가상 주소 공간 사이에 매핑을 생성하는 기법이다. 매핑이 끝나면 파일을 읽을 때마다 `read()`를 호출하는 대신, 메모리 주소를 배열처럼 역참조한다. 운영체제는 해당 주소에 접근할 때 페이지 폴트를 발생시키고, 필요한 파일 페이지를 메모리에 적재한다. 이후 접근은 메모리 접근처럼 처리된다.

매핑은 보통 `mmap()` 시스템 콜로 생성한다. 파일 디스크립터, 시작 오프셋, 매핑 크기, 보호 권한(`PROT_READ`, `PROT_WRITE`), 공유 방식(`MAP_SHARED`, `MAP_PRIVATE`)을 지정한다. `MAP_SHARED`는 변경 내용이 파일과 다른 프로세스에 반영될 수 있어 프로세스 간 공유 메모리처럼 사용할 수 있다. 반면 `MAP_PRIVATE`는 Copy-on-Write 방식이므로 수정해도 원본 파일은 바뀌지 않는다.

장점은 대용량 파일의 랜덤 접근, 반복적인 파일 접근, 프로세스 간 데이터 공유에 있다. 커널 페이지 캐시를 활용하고 사용자 공간 버퍼로 불필요하게 복사하는 비용을 줄일 수 있다. 다만 파일 크기보다 큰 영역을 접근하면 오류가 발생할 수 있으며, 매핑 중 파일이 삭제되거나 축소되면 `SIGBUS`가 발생할 수 있다. 여러 프로세스가 같은 매핑을 수정할 때는 원자성이나 락을 별도로 보장해야 한다.

수정 내용을 즉시 디스크에 기록해야 한다면 `flush()` 또는 운영체제의 `msync()` 계열 기능을 사용한다. 매핑이 파일 전체를 한 번에 메모리에 올린다는 뜻은 아니며, 메모리 압박이 발생하면 페이지가 다시 제거될 수 있다. 따라서 “항상 RAM에 상주한다”거나 “무조건 더 빠르다”는 해석은 피해야 한다.

## 코드 예제

```python
import mmap
from pathlib import Path

path = Path("data.bin")
path.write_bytes(b"hello memory map\n")

with path.open("r+b") as f:
    with mmap.mmap(f.fileno(), 0, access=mmap.ACCESS_WRITE) as mm:
        print(mm[:5])                 # b'hello'
        mm[6:12] = b"mapped"          # 파일 내용을 직접 수정
        mm.flush()                    # 변경 내용 반영

print(path.read_bytes())              # b'hello mapped map\n'
```

## 면접 질문

### 1. `MAP_SHARED`와 `MAP_PRIVATE`의 차이는?

`MAP_SHARED`는 매핑 영역의 변경이 파일과 다른 매핑에 공유될 수 있다. `MAP_PRIVATE`는 Copy-on-Write로 동작해 수정 시 개인 페이지가 생성되며 원본 파일에는 반영되지 않는다.

### 2. 메모리 매핑 파일이 항상 `read()`보다 빠른가?

아니다. 작은 파일의 순차 읽기에서는 일반 입출력이 더 단순하고 빠를 수 있다. 메모리 매핑은 대용량 파일, 랜덤 접근, 반복 접근에서 복사와 시스템 콜을 줄일 때 효과적이며 페이지 폴트와 매핑 관리 비용도 존재한다.

> **한 줄 정리:** 메모리 매핑 파일은 파일을 메모리 배열처럼 다루게 해 주지만, 페이지 폴트·동기화·파일 수명을 함께 관리해야 하는 최적화 기법이다.
