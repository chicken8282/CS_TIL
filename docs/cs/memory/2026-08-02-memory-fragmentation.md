# 메모리 단편화

- **외부 단편화**: 빈 공간은 충분하지만 조각나 있어 큰 메모리를 할당하지 못하는 현상
- **내부 단편화**: 할당받은 공간 중 실제로 사용하지 않는 부분이 생기는 현상
- 완화 방법으로 **메모리 풀, 페이징, 적절한 할당기** 등을 사용한다

## 개념 설명

메모리를 책장이라고 생각해 보자. 책장 전체에는 빈칸이 충분하지만, 여러 사람이 책을 빼고 넣다 보면 빈칸이 작은 조각으로 흩어진다. 이때 큰 책 한 권을 넣을 연속된 공간이 없으면, 전체 빈 공간은 충분해도 배치에 실패한다. 이것이 **외부 단편화**다.

예를 들어 메모리에 `사용 중 - 빈 공간 - 사용 중 - 빈 공간`처럼 배치되어 있고 빈 공간이 각각 30MB라면, 총 60MB가 비어 있어도 50MB짜리 연속 공간이 필요한 요청은 실패할 수 있다. 주로 가변 크기 메모리를 할당하고 해제하는 과정에서 발생한다.

반대로 **내부 단편화**는 책을 넣기 위해 책장 칸을 실제 크기보다 크게 예약하는 상황이다. 17바이트가 필요하지만 할당 단위가 8바이트라면 24바이트를 받고, 남은 7바이트는 해당 블록 안에서 사용하지 못할 수 있다. 고정 크기 블록, 정렬(alignment), 페이지 단위 할당에서 자주 나타난다.

운영체제의 **페이징**은 프로세스와 메모리를 고정 크기 페이지와 프레임으로 나누어 외부 단편화를 줄인다. 다만 마지막 페이지의 남는 공간처럼 내부 단편화가 생길 수 있다. 메모리 할당기는 빈 블록을 합치는 병합(coalescing), 적절한 크기별 관리, 메모리 풀 등으로 문제를 완화한다. 단편화는 단순히 “메모리가 부족하다”는 뜻이 아니라, **빈 공간의 배치와 사용 효율이 나빠진 상태**라는 점이 핵심이다.

## 코드 예시

```c
void *a = malloc(30);
void *b = malloc(30);
void *c = malloc(30);

free(b);              // 가운데에 작은 빈 공간 발생
void *d = malloc(50);  // 전체 여유가 있어도 연속 공간이 없을 수 있음

free(a);
free(c);              // 할당기가 인접 빈 블록을 병합할 수 있음
```

## 면접 질문

### 1. 외부 단편화와 내부 단편화의 차이는?

외부 단편화는 할당된 블록 **바깥의 빈 공간이 조각나는 현상**이고, 내부 단편화는 할당된 블록 **안에서 남는 공간이 낭비되는 현상**이다.

### 2. 페이징은 단편화를 어떻게 줄이는가?

메모리를 고정 크기 프레임으로 나누어 연속된 큰 공간이 필요하지 않게 하므로 외부 단편화를 줄인다. 대신 페이지의 남는 공간 때문에 내부 단편화가 발생할 수 있다.

> **한 줄 요약:** 메모리 단편화는 빈 공간이 부족한 것보다, 빈 공간을 효율적으로 쓰지 못하는 문제다.
