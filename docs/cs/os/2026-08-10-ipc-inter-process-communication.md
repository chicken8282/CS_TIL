# IPC(Inter-Process Communication)

## 핵심 요약

- **IPC는 서로 다른 프로세스가 데이터를 주고받는 방법**이다.
- 대표 방식은 **파이프, 메시지 큐, 공유 메모리, 소켓, 시그널**이다.
- 프로세스 간 메모리는 기본적으로 분리되므로, IPC에는 **데이터 전달과 동기화**가 함께 필요하다.

## 개념 설명

프로세스를 각각 **서로 다른 방**이라고 생각하면 쉽다. 한 방의 사람이 다른 방의 사람에게 직접 물건을 건넬 수는 없다. 대신 우편함, 전화, 공용 창고 같은 통신 수단을 사용해야 한다. 이 통신 수단이 IPC다.

프로세스는 안정성과 보안을 위해 각자 독립된 주소 공간을 가진다. 따라서 한 프로세스의 변수나 객체를 다른 프로세스가 바로 읽을 수 없다. 운영체제는 프로세스 사이에 데이터를 전달할 수 있도록 여러 IPC 방식을 제공한다.

- **파이프(Pipe)**: 부모-자식처럼 관계가 있는 프로세스 사이의 일방향 통로다. 작은 데이터를 순서대로 전달하기 쉽다.
- **메시지 큐(Message Queue)**: 우편함처럼 메시지를 넣고 꺼낸다. 송신자와 수신자가 동시에 실행되지 않아도 된다.
- **공유 메모리(Shared Memory)**: 공용 창고를 함께 사용하는 방식이다. 가장 빠를 수 있지만 동시에 수정하면 경쟁 조건이 발생하므로 락 같은 동기화가 필요하다.
- **소켓(Socket)**: 같은 컴퓨터뿐 아니라 네트워크 너머의 프로세스와도 통신할 수 있다. 클라이언트-서버 구조에서 자주 사용한다.
- **시그널(Signal)**: “종료해라”, “다시 처리해라”처럼 짧은 이벤트를 알리는 방식이다. 큰 데이터 전달보다는 상태 통지에 적합하다.

예를 들어 웹 서버가 작업 프로세스에 요청을 전달한다면 메시지 큐나 소켓을 사용할 수 있다. 대용량 데이터를 빠르게 공유해야 한다면 공유 메모리를 선택하되, 읽기·쓰기 순서를 조정해야 한다. 방식 선택 기준은 **데이터 크기, 통신 방향, 속도, 프로세스 관계, 장애 격리 필요성**이다.

## 코드 예시: Python 파이프

```python
from multiprocessing import Process, Pipe

def worker(conn):
    value = conn.recv()
    conn.send(value * 2)
    conn.close()

parent, child = Pipe()
p = Process(target=worker, args=(child,))
p.start()

parent.send(21)
print(parent.recv())  # 42

p.join()
parent.close()
```

## 면접 질문

### 1. 프로세스와 스레드의 IPC 차이는?

스레드는 같은 프로세스의 메모리를 공유하므로 변수로 통신할 수 있지만 동기화가 중요하다. 프로세스는 메모리가 분리되어 IPC가 필요하지만 장애가 서로 전파될 가능성이 낮다.

### 2. 공유 메모리는 빠른데 왜 락이 필요한가?

여러 프로세스가 같은 영역을 동시에 읽고 쓰면 데이터가 꼬이는 경쟁 조건이 발생한다. 따라서 뮤텍스, 세마포어 등으로 임계 구역의 접근 순서를 제어해야 한다.

## 한 줄 정리

**IPC는 독립된 프로세스들이 파이프·큐·공유 메모리·소켓 등을 통해 데이터를 전달하고 동기화하는 운영체제 기능이다.**
