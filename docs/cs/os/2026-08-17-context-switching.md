# 컨텍스트 스위칭(Context Switching)

- CPU가 실행 중인 프로세스나 스레드를 멈추고 다른 작업으로 교체하는 과정이다.
- 현재 작업의 상태를 저장하고, 다음 작업의 상태를 복원해야 한다.
- 교체 자체는 유용하지만 저장·복원과 캐시 손실 때문에 비용이 발생한다.

## 개념 설명

컨텍스트 스위칭은 **책상에서 공부하던 학생이 다른 과목의 공부로 바꾸는 상황**과 비슷하다. 운영체제는 CPU라는 책상을 여러 프로세스와 스레드가 나누어 쓰도록 관리한다.

현재 작업을 잠시 멈출 때 운영체제는 현재 작업의 **컨텍스트(context)** 를 저장한다. 컨텍스트에는 CPU 레지스터, 프로그램 카운터(다음에 실행할 주소), 스택 포인터 등이 포함된다. 프로세스라면 주소 공간 정보까지 관리할 수 있으며, 스레드는 같은 프로세스의 메모리를 공유하므로 주로 레지스터와 스택 상태를 저장한다.

그다음 실행할 작업의 컨텍스트를 불러와 CPU에 복원한다. 저장된 프로그램 카운터 덕분에 해당 작업은 중단된 지점부터 다시 실행된다. 이 정보는 프로세스 제어 블록(PCB)이나 스레드 제어 블록(TCB)에 관리된다.

스위칭은 타이머 인터럽트, 입출력 대기, 시스템 콜, 더 높은 우선순위 작업의 등장 등으로 발생한다. 예를 들어 실행 중인 프로세스가 디스크 입력을 기다리면 CPU를 계속 점유할 필요가 없으므로 다른 작업으로 전환한다.

컨텍스트 스위칭은 멀티태스킹의 핵심이지만 공짜가 아니다. 레지스터 저장·복원 시간이 필요하고, 새 작업의 메모리를 사용하면서 CPU 캐시와 TLB의 효율이 떨어질 수 있다. 일반적으로 **프로세스 전환이 스레드 전환보다 무겁다.** 프로세스는 주소 공간이 다르지만, 같은 프로세스의 스레드는 주소 공간을 공유하기 때문이다. 다만 실제 비용은 운영체제, 하드웨어, 캐시 상태에 따라 달라진다.

## 동작 예시

```c
void context_switch(Task *current, Task *next) {
    save_registers(&current->context);
    current->state = READY;

    next->state = RUNNING;
    load_registers(&next->context);
    jump_to(next->context.program_counter);
}
```

## 면접 질문

### 1. 컨텍스트 스위칭이란 무엇인가요?

CPU가 실행 대상을 바꿀 때 현재 작업의 레지스터와 프로그램 카운터 등을 저장하고, 다음 작업의 상태를 복원하는 과정입니다.

### 2. 프로세스 스위칭이 스레드 스위칭보다 일반적으로 무거운 이유는 무엇인가요?

프로세스는 서로 다른 주소 공간을 가지므로 메모리 매핑 변경과 TLB·캐시 영향이 더 큽니다. 스레드는 같은 프로세스의 주소 공간을 공유합니다.

## 한 줄 정리

**컨텍스트 스위칭은 CPU 작업을 바꾸기 위한 상태 저장·복원 과정이며, 멀티태스킹을 가능하게 하지만 전환 비용을 발생시킨다.**
