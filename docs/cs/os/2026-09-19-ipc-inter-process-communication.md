# IPC(프로세스 간 통신)

- **목적:** 서로 다른 프로세스가 데이터와 이벤트를 안전하게 교환하도록 한다.
- **주요 방식:** 파이프, 메시지 큐, 공유 메모리, 시그널, 소켓(특히 Unix Domain Socket).
- **실무 선택 기준:** 데이터 크기·지연 시간·신뢰성·프로세스 위치·장애 격리 수준을 함께 고려한다.

## 개념 설명

IPC는 메모리 공간이 분리된 프로세스 사이의 통신 방법이다. 같은 프로세스의 함수 호출과 달리, IPC는 커널이나 운영체제 자원을 거치므로 직렬화, 복사, 동기화 비용이 발생한다.

**파이프**는 부모-자식 프로세스처럼 관계가 명확한 프로세스 간 스트림 전달에 적합하다. 셸의 `ls | grep log`가 대표 사례다. **메시지 큐**는 작업을 메시지 단위로 전달하므로 비동기 작업 처리, 재시도, 소비자 확장에 유리하다. 웹 서버가 이미지 리사이징 작업을 큐에 넣고 워커가 처리하는 구조에서 자주 사용한다.

**공유 메모리**는 대용량 데이터를 복사하지 않아 빠르지만, 락·세마포어 등 동기화가 필요하다. 잘못 구현하면 경쟁 조건과 교착 상태가 발생한다. **소켓**은 같은 호스트에서는 Unix Domain Socket, 다른 호스트까지 확장할 때 TCP를 사용한다. Nginx와 애플리케이션 서버 연결, Docker 데몬 API, 로컬 에이전트 통신이 실무 사례다.

운영 환경에서는 메시지 포맷과 버전 호환성, 타임아웃, 버퍼 포화에 따른 백프레셔, 송수신 프로세스 종료 처리, 접근 권한을 반드시 정의해야 한다. IPC 자체가 신뢰성을 보장하지 않으므로 재시도 시 중복 처리와 멱등성도 설계해야 한다. 장애 분석을 위해 메시지 ID, 처리 시간, 큐 길이, 실패율을 기록하면 효과적이다.

## 코드 예시: Python 멀티프로세스 작업 큐

```python
from multiprocessing import Process, Queue

def worker(tasks, results):
    for task in iter(tasks.get, None):
        results.put((task, task * task))

if __name__ == "__main__":
    tasks, results = Queue(), Queue()
    p = Process(target=worker, args=(tasks, results))
    p.start()

    for n in range(3):
        tasks.put(n)
    tasks.put(None)          # 종료 신호
    p.join()

    while not results.empty():
        print(results.get())
```

## 면접 질문

1. **공유 메모리가 빠른데 항상 사용하지 않는 이유는?**  
   동기화가 어렵고 경쟁 조건·교착 상태 위험이 있다. 작은 메시지는 큐나 소켓이 운영 복잡도 측면에서 더 적합하다.

2. **IPC에서 메시지 중복 처리에 어떻게 대응하는가?**  
   메시지 ID와 멱등 키를 사용하고, 처리 결과를 저장한 뒤 재시도해도 상태가 한 번만 반영되도록 설계한다.

> **한 줄 요약:** IPC는 프로세스 경계를 넘는 통신이며, 실무에서는 성능보다 장애·동기화·재처리까지 포함해 선택해야 한다.
