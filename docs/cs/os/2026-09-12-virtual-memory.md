# 가상 메모리

- 프로세스마다 독립적인 가상 주소 공간을 제공해 메모리 격리와 실행 안정성을 높인다.
- 필요한 페이지만 실제 RAM에 적재하는 수요 페이징으로 메모리를 효율적으로 사용한다.
- TLB, 페이지 폴트, 스왑, 컨테이너 메모리 제한을 이해해야 성능 문제를 진단할 수 있다.

## 개념 설명

가상 메모리는 프로세스가 직접 물리 메모리 주소를 사용하지 않고, 가상 주소를 사용하도록 하는 운영체제 기능이다. CPU의 MMU가 페이지 테이블을 참고해 가상 주소를 물리 주소로 변환한다. 일반적으로 가상 주소 공간은 고정 크기의 페이지로, 물리 메모리는 페이지 프레임으로 나뉜다.

프로세스가 접근한 페이지가 RAM에 있으면 TLB 또는 페이지 테이블을 통해 빠르게 접근한다. 반대로 페이지가 아직 적재되지 않았으면 페이지 폴트가 발생하고, 운영체제는 디스크나 파일에서 페이지를 읽어온 뒤 실행을 재개한다. 이 과정은 매우 느리므로 무작위 대용량 메모리 접근은 성능 저하의 원인이 된다.

현업에서는 가상 메모리가 여러 문제를 해결한다. 각 프로세스가 다른 프로세스의 메모리를 임의로 읽지 못하게 해 장애와 보안 문제를 격리한다. `fork` 후에는 Copy-on-Write를 사용해 부모와 자식이 같은 페이지를 공유하다가 수정 시에만 복사하므로 프로세스 생성 비용을 줄인다. 데이터베이스, JVM, 캐시 서버는 큰 주소 공간을 활용하지만, 실제 RSS와 페이지 폴트율을 함께 확인해야 한다.

컨테이너도 가상 메모리를 사용하지만 호스트의 메모리를 무제한으로 보장하지 않는다. cgroup 제한을 초과하면 OOM Killer가 프로세스를 종료할 수 있다. 운영 환경에서는 `free`, `vmstat`, `/proc/<pid>/smaps`, 컨테이너 메트릭으로 RSS, 스왑, major page fault를 점검한다. 메모리 누수와 단순한 가상 주소 예약을 구분하는 것도 중요하다.

## 코드 예시

```c
#include <sys/mman.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    size_t n = 1024 * 1024 * 1024;
    char *p = mmap(NULL, n, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) return 1; // 주소 공간 예약 실패
    p[0] = 1;                       // 실제 페이지가 필요해짐
    printf("%d\n", p[0]);
    munmap(p, n);
}
```

`mmap`은 큰 가상 주소 공간을 예약할 수 있지만, 실제 물리 메모리는 페이지에 처음 접근할 때 수요에 따라 할당된다. 따라서 `mmap` 성공만으로 RAM이 확보됐다고 판단하면 안 된다.

## 면접 질문

### 1. 페이지 폴트는 항상 오류인가?

아니다. 페이지가 RAM에 없다는 이벤트다. 운영체제가 정상적으로 페이지를 적재하면 복구되지만, 잘못된 주소 접근이면 프로세스가 종료된다. Major fault는 디스크 I/O를 포함해 특히 느리다.

### 2. TLB가 필요한 이유는?

페이지 테이블 조회 결과를 캐시해 가상 주소 변환 비용을 줄이기 위해서다. TLB 미스가 많으면 메모리 접근 시간이 증가하므로 큰 페이지, 지역성 개선, 적절한 메모리 배치가 성능에 영향을 준다.

> **한 줄 정리:** 가상 메모리는 주소 공간 격리와 효율적 메모리 사용을 제공하지만, 페이지 폴트와 실제 RSS를 함께 관리해야 한다.
