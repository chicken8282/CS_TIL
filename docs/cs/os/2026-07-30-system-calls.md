# 시스템 콜과 성능 최적화

- **시스템 콜은 사용자 모드에서 커널 모드로 전환하는 비용이 있는 경계 호출**이다.
- **호출 횟수와 데이터 복사량을 줄이는 것**이 성능 최적화의 핵심이다.
- `read`, `write`, `open`, `fork`, `mmap`, `epoll_wait` 등은 목적과 비용 특성이 서로 다르다.

## 개념 설명

시스템 콜(System Call)은 애플리케이션이 운영체제 커널의 기능을 요청하는 인터페이스다. 일반 코드는 사용자 모드에서 실행되지만 파일, 네트워크, 프로세스, 메모리 매핑 같은 자원은 커널이 관리하므로 시스템 콜을 통해 접근한다.

호출 과정에서는 함수 호출만 발생하는 것이 아니라 권한 수준 전환, 레지스터 저장·복구, 커널 진입 및 복귀, 인자 검증 등이 수행된다. 따라서 짧은 작업을 반복적으로 시스템 콜로 처리하면 실제 작업보다 경계 전환 비용이 커질 수 있다. 특히 작은 데이터를 한 번씩 `write()`하는 방식은 큰 데이터를 모아 한 번 `write()`하는 방식보다 비효율적이다.

성능 최적화에서는 먼저 프로파일러나 `strace -c`, `perf`, eBPF 도구로 시스템 콜 횟수와 지연 시간을 확인해야 한다. 단순히 시스템 콜을 줄이는 것이 항상 정답은 아니다. 블로킹 호출로 스레드가 오래 대기하거나, 큰 버퍼를 사용해 메모리 사용량과 지연 시간이 증가할 수도 있기 때문이다.

대표적인 최적화 방법은 다음과 같다.

- 작은 읽기·쓰기를 버퍼링하여 배치 처리한다.
- 파일 접근 시 적절한 버퍼 크기와 `mmap()` 사용 여부를 비교한다.
- 네트워크 서버는 연결마다 블로킹 호출을 수행하기보다 `epoll` 같은 이벤트 기반 모델을 검토한다.
- 프로세스 간 데이터 전달에서는 불필요한 복사를 줄이고 공유 메모리를 고려한다.
- `fsync()`는 내구성을 보장하지만 비용이 크므로 필요한 시점에만 호출한다.
- 시스템 콜 수뿐 아니라 p99 지연 시간, 처리량, CPU 사용률을 함께 측정한다.

## 코드 예시: 작은 쓰기를 버퍼링하기

```c
#include <unistd.h>
#include <string.h>

int main(void) {
    const char *msg = "event\n";
    char buf[4096];
    size_t used = 0;

    for (int i = 0; i < 1000; i++) {
        size_t n = strlen(msg);
        if (used + n > sizeof(buf)) {
            write(STDOUT_FILENO, buf, used);
            used = 0;
        }
        memcpy(buf + used, msg, n);
        used += n;
    }
    if (used) write(STDOUT_FILENO, buf, used);
}
```

위 코드는 `write()`를 반복 호출하는 대신 여러 데이터를 버퍼에 모아 호출 횟수를 줄인다. 실제 서비스에서는 `write()`의 반환값, 부분 쓰기, `EINTR` 처리도 확인해야 한다.

## 면접 질문

### 1. 시스템 콜이 일반 함수 호출보다 느린 이유는?

사용자 모드에서 커널 모드로 전환하고, 레지스터와 권한을 관리하며, 커널이 인자를 검증하는 추가 비용이 발생하기 때문이다. 반복 호출을 줄이기 위해 버퍼링과 배치 처리를 적용할 수 있다.

### 2. 시스템 콜 횟수를 줄이면 항상 성능이 좋아지는가?

아니다. 큰 배치는 메모리 사용량과 응답 지연을 늘릴 수 있고, `fsync()`처럼 호출 목적상 생략할 수 없는 작업도 있다. 호출 횟수뿐 아니라 처리량, 지연 시간, CPU·메모리 사용량을 함께 측정해야 한다.

> **한 줄 정리:** 시스템 콜 최적화는 무조건 제거하는 것이 아니라, 측정에 기반해 호출 횟수·복사·대기 시간을 균형 있게 줄이는 작업이다.
