# 시간 복잡도(Time Complexity)

## 핵심 포인트

- 시간 복잡도는 입력 크기 `n`에 따라 연산 횟수가 어떻게 증가하는지 나타내며, 실제 실행 시간과는 구분한다.
- 가장 빠른 증가율을 기준으로 빅오(Big-O)를 사용해 상한을 표현하고, 상수와 낮은 차수는 일반적으로 제거한다.
- 반복문 개수만 세지 말고, 정렬·재귀·자료구조 연산의 비용과 최악·평균·상각 복잡도를 함께 판단해야 한다.

## 개념 설명

시간 복잡도는 알고리즘의 효율성을 입력 크기 `n`의 함수로 분석하는 방법이다. 예를 들어 배열을 처음부터 끝까지 탐색하면 최대 `n`번 비교하므로 `O(n)`이다. 중첩 반복문이 각각 `n`번 실행되면 `O(n²)`이며, 매 단계마다 탐색 범위를 절반으로 줄이면 `O(log n)`이다.

빅오 표기법은 증가율에 집중한다. `3n + 10`은 `O(n)`, `2n² + n`은 `O(n²)`로 표현한다. 일반적인 증가 순서는 `O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)`이다. 다만 입력이 작거나 상수 비용이 큰 경우 실제 성능은 다를 수 있다.

분석할 때는 최선, 평균, 최악의 경우를 구분한다. 해시 테이블 조회는 평균적으로 `O(1)`이지만 충돌이 집중되면 최악 `O(n)`이 될 수 있다. 또한 동적 배열의 `append`는 대부분 `O(1)`이지만 용량 확장과 복사까지 고려하면 개별 연산의 최악은 `O(n)`, 여러 번 수행한 평균 비용인 상각 복잡도는 `O(1)`이다.

시간 복잡도와 공간 복잡도는 함께 판단해야 한다. 예를 들어 정렬된 배열에서 이진 탐색은 `O(log n)`이지만, 정렬 자체에 `O(n log n)`이 필요할 수 있다. 면접에서는 “반복문이 몇 개인가?”보다 입력 크기, 자료구조의 내부 동작, 정렬 여부, 재귀 호출 수를 근거로 설명하는 것이 중요하다.

## 코드 예시

```python
def has_duplicate(nums):
    seen = set()

    for number in nums:       # O(n)
        if number in seen:    # 평균 O(1)
            return True
        seen.add(number)      # 평균 O(1)

    return False              # 전체 평균 O(n)
```

## 면접 질문

### 1. `O(n)`과 `O(1)` 중 항상 `O(1)`이 더 빠른가요?

아니다. 빅오는 입력 크기가 커질 때의 증가율만 나타낸다. 작은 입력에서는 상수 비용, 캐시 효율, 구현 언어에 따라 `O(n)`이 더 빠를 수 있다.

### 2. 이진 탐색의 시간 복잡도는 왜 `O(log n)`인가요?

한 번 비교할 때마다 탐색 범위가 절반으로 줄어들기 때문이다. `n`을 계속 2로 나누어 1이 되는 횟수가 `log₂n`이므로 `O(log n)`이다. 단, 데이터가 정렬되어 있어야 한다.

## 한 줄 정리

> 시간 복잡도는 코드의 반복 횟수가 아니라 입력 크기에 따른 증가율과 자료구조 연산 비용을 분석하는 기준이다.
