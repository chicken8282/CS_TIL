# RISC vs CISC: 성능 최적화 관점

- **RISC**는 단순하고 길이가 일정한 명령어를 사용해 파이프라인, 레지스터 활용, 병렬 실행에 유리하다.
- **CISC**는 하나의 복합 명령어로 많은 작업을 수행해 코드 크기와 메모리 접근 횟수를 줄일 수 있다.
- 현대 CPU에서는 경계가 약해졌다. x86(CISC)도 내부적으로 명령어를 마이크로 연산으로 분해하고, ARM(RISC)도 복잡한 실행 최적화를 수행한다.

## 개념 설명

RISC(Reduced Instruction Set Computer)는 `load`, `add`, `store`처럼 역할이 분리된 명령어를 중심으로 설계된다. 명령어 형식이 단순하고 대체로 일정하므로 디코딩 비용이 낮고, 파이프라인을 균일하게 유지하기 쉽다. 대신 하나의 고수준 연산이 여러 명령어로 늘어날 수 있어 레지스터와 명령어 캐시 사용량이 증가할 수 있다.

CISC(Complex Instruction Set Computer)는 메모리 피연산자를 직접 더하는 등 복합 명령어를 제공한다. 프로그램 크기가 작아지고 명령어 fetch 횟수가 줄어드는 장점이 있지만, 명령어별 실행 시간이 달라 디코더와 파이프라인이 복잡해진다.

성능은 ISA 종류만으로 결정되지 않는다. 실제 병목은 **메모리 지연, 캐시 적중률, 분기 예측, 명령어 수준 병렬성, 컴파일러 최적화**인 경우가 많다. 예를 들어 반복문에서는 ISA보다 연속적인 메모리 접근, 데이터 정렬, 불필요한 분기 제거가 더 큰 효과를 낸다. RISC 환경에서는 명령어 수 증가로 인한 I-cache 압박을 확인하고, CISC 환경에서는 복합 명령어가 항상 빠르다고 가정하지 말아야 한다. 프로파일러와 벤치마크로 hot path를 측정하고, 컴파일러가 생성한 어셈블리와 캐시·분기 성능을 함께 분석해야 한다.

```asm
; CISC: 메모리 피연산자를 직접 갱신
add [sum], eax

; RISC: load, 연산, store를 분리
ldr  t0, [sum]
add  t0, t0, a0
str  t0, [sum]
```

## 면접 질문

1. **RISC가 항상 CISC보다 빠른가?**  
   아니다. 성능은 명령어 수보다 마이크로아키텍처, 캐시, 분기 예측, 컴파일러, workload에 좌우된다.

2. **x86은 CISC인데 어떻게 높은 성능을 내는가?**  
   복합 명령어를 내부의 단순한 마이크로 연산으로 변환하고, 비순차 실행·레지스터 재명명·분기 예측으로 병렬성을 확보한다.

> **한 줄 정리:** RISC와 CISC의 선택보다 실제 성능 최적화에서는 캐시, 분기, 병렬성, 컴파일러가 만드는 실행 경로를 측정하는 것이 중요하다.
