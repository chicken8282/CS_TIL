# 시간 복잡도: 자주 하는 실수와 안티패턴

- 입력 크기 `n`이 커질 때 실행 시간이 어떻게 증가하는지 Big-O로 표현한다.
- 반복문 개수보다 **반복 횟수와 입력 간 의존성**을 분석해야 한다.
- 평균·최악·상각 시간 복잡도를 구분하고, 공간 복잡도와 함께 판단한다.

## 개념 설명

시간 복잡도는 실제 실행 시간이 아니라 입력 크기 `n`에 따른 증가율이다. 상수와 낮은 차수는 일반적으로 제거해 `O(2n + 10)`을 `O(n)`으로 표현한다. 대표적인 순서는 `O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)`이다.

가장 흔한 실수는 중첩 반복문을 무조건 `O(n²)`로 보는 것이다. 안쪽 반복 횟수가 `n`과 무관하면 전체는 `O(n)`이고, 매번 범위가 절반으로 줄면 `O(log n)`이다. 반대로 서로 독립적인 반복문은 중첩이 아니므로 `O(n + n)`은 `O(n)`이다.

조건문은 실행 경로 중 가장 큰 비용을 기준으로 본다. `if`와 `else` 중 하나만 실행된다면 합이 아니라 최댓값을 선택한다. 함수 호출도 내부 복잡도를 반드시 확인해야 한다. 겉으로는 한 줄인 `list.includes()`가 배열에서는 `O(n)`일 수 있으며, 이를 반복문 안에서 호출하면 `O(n²)`이 된다.

자료구조의 비용도 확인해야 한다. 배열 앞부분 삽입·삭제는 요소 이동 때문에 `O(n)`이고, 해시 조회는 평균 `O(1)`이지만 충돌이 심하거나 최악의 경우 `O(n)`이 될 수 있다. 정렬은 일반적으로 `O(n log n)`이며, 정렬 후 선형 탐색을 사용하면 전체도 `O(n log n)`이다.

또 다른 안티패턴은 Big-O만 보고 실제 성능을 무시하는 것이다. `O(n)`이라도 큰 상수, 캐시 비효율, 메모리 할당, I/O가 병목일 수 있다. 반대로 작은 입력에서는 `O(n²)`가 더 단순하고 빠를 수 있다. 평균 복잡도만 보고 최악 입력을 놓치지 말고, 재귀에서는 호출 횟수와 스택 공간도 함께 분석한다.

## 코드 예시

```python
def has_duplicate_bad(nums):
    for i in range(len(nums)):
        if nums[i] in nums[i + 1:]:  # 매번 슬라이싱·탐색
            return True
    return False  # 최악 O(n^2), 추가 공간도 발생

def has_duplicate_good(nums):
    seen = set()
    for value in nums:
        if value in seen:           # 평균 O(1)
            return True
        seen.add(value)
    return False  # 평균 O(n), 공간 O(n)
```

## 면접 질문

### Q1. 중첩 반복문은 항상 `O(n²)`인가?

아니다. 반복 범위가 고정이면 `O(n)`, 안쪽 변수가 절반씩 감소하면 `O(n log n)`처럼 실제 반복 횟수를 계산해야 한다.

### Q2. 해시셋 조회는 항상 `O(1)`인가?

평균적으로 `O(1)`이지만 해시 충돌이 집중되면 최악 `O(n)`이 될 수 있다. 면접에서는 평균과 최악을 구분해 답한다.

## 한 줄 정리

시간 복잡도는 반복문 개수가 아니라 **입력 크기에 따른 실제 연산 증가율**을 분석하는 것이다.
