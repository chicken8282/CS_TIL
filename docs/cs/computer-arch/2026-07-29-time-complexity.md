# 시간 복잡도: 내부 구현 관점에서 이해하기

- 시간 복잡도는 입력 크기 `n`에 따라 **연산 횟수가 어떻게 증가하는지** 나타낸다.
- `O(1)`, `O(log n)`, `O(n)`, `O(n log n)`, `O(n²)`는 실행 시간의 절대값이 아니라 성장률이다.
- 같은 `O(n)`이라도 메모리 접근, 캐시 적중, 분기, 재할당 여부에 따라 실제 성능은 크게 달라진다.

## 개념 설명

시간 복잡도는 프로그램을 실행해 걸린 시간을 측정하는 방식이 아니라, 입력 크기에 따른 핵심 연산 수를 세어 분석한다. 상수와 낮은 차수는 일반적으로 제거하므로 `3n + 10`은 `O(n)`, `n² + n`은 `O(n²)`로 표현한다. 다만 실제 시스템에서는 상수 비용도 중요하다. 배열 순회는 연속된 메모리를 읽어 CPU 캐시 효율이 높지만, 연결 리스트 순회는 노드 포인터를 따라가며 캐시 미스가 발생하기 쉽다.

반복문이 입력을 매번 절반으로 줄이면 `O(log n)`이다. 이진 탐색이 대표적이며, 정렬된 배열에서 중간 원소를 확인하고 탐색 범위를 반으로 줄인다. 서로 독립적인 반복문은 더해지고, 중첩 반복문은 곱해진다. 따라서 바깥 루프가 `n`번, 안쪽 루프가 `n`번 실행되면 `O(n²)`이다.

동적 배열의 `append`는 평소 `O(1)`이지만 용량이 가득 차면 더 큰 배열을 할당하고 전체 원소를 복사하므로 해당 순간에는 `O(n)`이다. 그러나 용량을 보통 2배씩 늘리면 여러 삽입에 대한 평균 비용은 `O(1)`인 **분할 상환 시간**이 된다. 해시 테이블도 평균 조회는 `O(1)`이지만 해시 충돌이 많으면 최악 `O(n)`까지 증가한다.

정렬의 `O(n log n)`은 비교 기반 정렬에서 흔하다. 병합 정렬은 분할 깊이가 `log n`, 각 단계의 병합 비용이 `n`이라서 이 복잡도를 갖는다. 시간 복잡도 분석에서는 최선, 평균, 최악의 경우를 구분하고, 입력이 이미 정렬되었는지와 같은 데이터 분포도 함께 고려해야 한다.

```python
def has_duplicate(values):
    seen = set()
    for value in values:          # 평균 O(1) 조회
        if value in seen:
            return True
        seen.add(value)           # 전체 평균 O(n)
    return False

def pair_sum(values):
    for i in range(len(values)): # n
        for j in range(i + 1, len(values)): # 최대 n
            if values[i] + values[j] == 0:
                return True
    return False                  # O(n²)
```

## 면접 질문

### 1. 동적 배열의 `append`가 왜 평균 `O(1)`인가요?

용량이 부족할 때 배열을 확장하고 기존 원소를 복사하지만, 보통 용량을 2배로 늘린다. 복사 비용이 특정 삽입에 집중되더라도 여러 삽입 전체로 분산하면 원소 하나당 평균 비용은 `O(1)`이다.

### 2. 해시 테이블 조회가 항상 `O(1)`인가요?

아니다. 평균적으로 해시 함수가 키를 균등하게 분산하면 `O(1)`이지만, 충돌이 집중되면 연결 리스트나 트리 탐색이 필요해 최악 `O(n)`이 될 수 있다. 실제 구현은 리사이징과 충돌 관리로 이를 완화한다.

## 한 줄 정리

시간 복잡도는 반복 횟수만 세는 것이 아니라, 자료구조의 내부 연산·메모리 접근·재할당까지 반영해 입력 증가에 따른 비용을 예측하는 방법이다.
