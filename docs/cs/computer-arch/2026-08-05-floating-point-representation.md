# 부동소수점 표현과 내부 구현

- **IEEE 754**는 부호, 지수, 가수 필드로 실수를 저장하며, `float`는 32비트, `double`은 보통 64비트다.
- 저장값은 정수처럼 “정확한 실수”가 아니라 `유효숫자 × 2의 지수` 형태의 근삿값이다.
- CPU는 부동소수점 전용 레지스터와 FPU 또는 SIMD 명령어를 사용하며, 반올림·오버플로·비정상 수를 하드웨어 수준에서 처리한다.

## 개념 설명

IEEE 754 단정도 `float`는 다음처럼 구성된다.

```text
부호 1비트 | 지수 8비트 | 가수 23비트
```

정규화된 수의 값은 `(-1)^부호 × 1.가수 × 2^(지수-127)`이다. 지수에 바이어스 127을 더해 저장하므로 음수 지수도 unsigned 필드로 표현할 수 있다. 배정도 `double`은 `1 | 11 | 52`비트 구조와 바이어스 1023을 사용한다.

가수 앞의 `1`은 정규화된 값에서 항상 존재하므로 실제 정밀도에는 포함하지 않는 **숨은 비트**다. 반면 지수가 0이면 숨은 비트가 없는 비정규화 수로 해석되어 0에 가까운 값을 점진적으로 표현한다. 지수가 최대이면 가수가 0일 때 무한대, 0이 아니면 NaN이다.

십진수 `0.1`은 이진수로 무한히 반복되므로 유한한 가수 비트에 맞춰 반올림된다. 따라서 `0.1 + 0.2 == 0.3`이 거짓일 수 있다. 기본 반올림은 보통 “가장 가까운 값, 짝수 우선”이며, 연산 중간 결과가 반올림되므로 연산 순서에 따라 결과가 달라진다.

실제 덧셈에서는 먼저 작은 지수의 가수를 정렬하고, 가수를 더한 뒤, 정규화와 반올림을 수행한다. 이 과정에서 가드 비트·라운드 비트·스티키 비트를 사용해 버려지는 비트의 영향을 판단한다. 비교 시에는 허용 오차를 사용하고, 금액·카운터처럼 정확성이 필요한 값은 정수 스케일링이나 decimal 타입을 고려해야 한다.

```c
#include <stdint.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    float x = 0.1f;
    uint32_t bits;
    memcpy(&bits, &x, sizeof bits);

    printf("sign=%u exp=%u frac=0x%06x\n",
           bits >> 31, (bits >> 23) & 0xff, bits & 0x7fffff);
}
```

## 면접 질문

1. **왜 `0.1 + 0.2 == 0.3`이 실패하는가?**  
   `0.1`, `0.2`, `0.3`이 이진수로 정확히 표현되지 않아 서로 다른 근삿값으로 저장되기 때문이다.

2. **정규화 수와 비정규화 수의 차이는 무엇인가?**  
   정규화 수는 가수 앞의 숨은 `1`을 사용해 정밀도를 높이고, 비정규화 수는 숨은 비트 없이 표현해 0에 점진적으로 접근하도록 한다.

> **한 줄 요약:** 부동소수점은 비트 수가 제한된 이진 근사 표현이므로, 필드 구조·반올림·특수값을 이해해야 정확한 연산과 디버깅이 가능하다.
