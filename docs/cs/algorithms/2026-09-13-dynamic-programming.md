# 동적 계획법(Dynamic Programming)과 실무 트러블슈팅

- **핵심은 상태(state), 점화식(transition), 초기값(base case)** 을 정확히 정의하는 것이다.
- 중복 계산을 메모이제이션으로 제거하고, 필요하면 바텀업으로 시간·메모리 사용량을 관리한다.
- 장애 원인은 알고리즘보다 **상태 정의 오류, 경계값 누락, 반복 순서 오류, 자료형·메모리 문제**에서 자주 발생한다.

## 개념 설명

동적 계획법(DP)은 큰 문제를 작은 부분 문제로 나누고, 부분 문제의 결과를 저장해 중복 계산을 피하는 기법이다. 적용 가능하려면 일반적으로 **최적 부분 구조**와 **부분 문제 중복**이 필요하다.

문제를 풀 때 먼저 “`dp[i]`가 무엇을 의미하는가?”를 한 문장으로 정의한다. 예를 들어 `dp[i]`를 “금액 `i`를 만드는 최소 동전 개수”라고 정하면, 동전 `c`를 마지막에 선택하는 경우 다음과 같이 전이할 수 있다.

`dp[i] = min(dp[i], dp[i-c] + 1)`

구현 방식은 두 가지다. 재귀와 캐시를 사용하는 톱다운은 코드가 직관적이지만 재귀 깊이와 함수 호출 비용을 확인해야 한다. 반복문을 사용하는 바텀업은 실행 흐름과 메모리 사용량을 예측하기 쉽다. 시간 복잡도는 보통 `상태 수 × 상태당 전이 수`로 계산한다.

실무 트러블슈팅에서는 먼저 작은 입력을 손으로 계산해 상태 의미와 기대 배열을 만든다. 이후 다음을 점검한다.

1. 불가능한 상태를 `0`으로 두지 않았는가? 최소화 문제에서는 `INF`가 필요할 수 있다.
2. `i-c`가 음수가 되는 경계를 처리했는가?
3. 조합과 순열을 구분해 반복문 순서를 올바르게 작성했는가?
4. 결과가 너무 커질 수 있으면 오버플로와 모듈러 연산을 처리했는가?
5. `O(NM)` 시간이나 `O(NM)` 메모리가 입력 제한에 맞는가?

디버깅 시 전체 배열을 무작정 출력하기보다, 특정 입력에서 각 상태가 갱신되는 조건과 이전 상태를 로그로 확인하면 원인을 빠르게 좁힐 수 있다.

```python
def min_coins(coins, amount):
    INF = amount + 1
    dp = [0] + [INF] * amount
    for total in range(1, amount + 1):
        for coin in coins:
            if coin <= total:
                dp[total] = min(dp[total], dp[total - coin] + 1)
    return -1 if dp[amount] == INF else dp[amount]
```

## 면접 질문

### 1. 메모이제이션과 바텀업의 차이는?

메모이제이션은 필요한 상태만 재귀적으로 계산하는 톱다운 방식이고, 바텀업은 작은 상태부터 반복적으로 계산하는 방식이다. 후자는 재귀 오버헤드와 스택 위험이 적다.

### 2. DP와 그리디의 차이는?

그리디는 현재 최선의 선택이 전체 최적해를 보장해야 한다. DP는 여러 선택의 결과를 비교하며 최적해를 보장하므로, 그리디 적용 가능성을 증명하기 어려울 때 안전한 선택이다.

> **한 줄 정리:** DP는 점화식보다 먼저 상태의 의미를 정의하고, 경계값·반복 순서·복잡도를 검증해야 실무에서 안정적으로 동작한다.
