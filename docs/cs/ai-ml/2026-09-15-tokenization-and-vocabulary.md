# 토큰화와 어휘(Vocabulary): 성능 최적화 관점

- **토큰화**는 텍스트를 모델이 처리할 수 있는 정수 ID 시퀀스로 변환하는 과정이며, 어휘 크기와 토큰 분할 방식이 추론 비용을 좌우한다.
- 어휘가 크면 평균 시퀀스 길이는 줄지만 **임베딩·출력 행렬 메모리**가 증가하고, 어휘가 작으면 메모리는 절약되지만 토큰 수와 연산량이 늘어난다.
- 운영 환경에서는 토크나이저 로딩, 정규화, 패딩, 배치 구성을 최적화해야 하며, 모델과 정확히 일치하는 토크나이저를 사용해야 한다.

## 개념 설명

토큰화는 문장을 단어, 부분 단어(subword), 문자 단위 등으로 나누고 각 토큰을 ID로 매핑한다. 대표적으로 BPE, WordPiece, Unigram 방식이 사용된다. 현대 언어 모델은 미등록 단어 문제와 다국어 처리를 고려해 보통 subword 토큰화를 사용한다.

어휘 크기 `V`는 임베딩 행렬 크기 `V × d`, 출력 로짓 크기 `batch × sequence × V`에 직접 영향을 준다. 따라서 `V`가 지나치게 크면 GPU 메모리와 softmax 비용이 커진다. 반대로 어휘가 작으면 동일한 문장이 더 많은 토큰으로 분해되어 attention 비용 `O(L²)`이 증가한다. 특히 긴 컨텍스트에서는 토큰 수를 줄이는 효과가 크다.

성능 최적화에서는 다음을 확인한다.

1. **토큰 길이 분포**: 평균뿐 아니라 p95, p99 길이를 측정해 긴 입력으로 인한 지연을 파악한다.
2. **패딩 최소화**: 길이가 비슷한 샘플끼리 묶는 length bucketing과 동적 패딩을 사용한다.
3. **처리 재사용**: 반복되는 프롬프트나 문서는 토큰 ID를 캐시하고, 토크나이저를 요청마다 초기화하지 않는다.
4. **배치 처리**: 개별 호출보다 여러 입력을 묶어 처리하되, 지나치게 긴 샘플이 전체 배치를 지배하지 않도록 한다.
5. **특수 토큰 일관성**: BOS, EOS, PAD, UNK 설정이 다르면 결과와 길이가 달라지므로 학습·추론 설정을 동일하게 유지한다.

```python
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("model", use_fast=True)
texts = ["짧은 문장", "조금 더 긴 문장입니다."]
batch = tok(
    texts, padding=True, truncation=True,
    max_length=512, return_tensors="pt"
)
lengths = batch["attention_mask"].sum(dim=1)
print(lengths.tolist())
```

## 면접 질문

### 1. 어휘 크기를 무작정 키우면 왜 성능이 좋아지지 않나요?

어휘가 커지면 시퀀스 길이는 줄 수 있지만 임베딩·출력 행렬과 softmax 비용, 메모리 사용량이 증가한다. 최적점은 언어, 데이터, 하드웨어, 컨텍스트 길이에 따라 달라진다.

### 2. 패딩이 추론 성능에 미치는 영향은 무엇인가요?

배치 내 최대 길이에 맞춰 계산하므로 짧은 입력의 패딩 비율이 높으면 불필요한 attention 연산이 발생한다. 동적 패딩, 길이 버킷, 시퀀스 패킹으로 낭비를 줄일 수 있다.

**한 줄 요약:** 좋은 토큰화 최적화는 어휘 크기, 토큰 길이, 패딩 비율, 캐시를 함께 조정해 메모리와 연산량을 균형 있게 줄이는 것이다.
