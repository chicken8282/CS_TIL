# 토크나이제이션과 어휘 사전

- **토크나이제이션(tokenization)**: 문장을 모델이 처리할 수 있는 토큰 단위로 분할하는 과정이다.
- **어휘 사전(vocabulary)**: 각 토큰과 정수 ID의 매핑 테이블이며, 모델 입력은 최종적으로 ID 시퀀스가 된다.
- 토큰화 방식은 **성능, 어휘 크기, 미등록 단어 처리, 비용**에 직접적인 영향을 준다.

## 개념 설명

컴퓨터는 문자열을 그대로 이해하지 못하므로 문장을 토큰으로 나눈 뒤, 각 토큰을 정수 ID로 변환한다. 예를 들어 `"나는 밥을 먹었다"`는 공백 기준으로 나눌 수도 있고, 형태소 또는 서브워드 단위로 나눌 수도 있다.

대표적인 방식은 다음과 같다.

1. **문자 단위**: 모든 문자를 토큰으로 사용한다. 어휘가 작지만 시퀀스가 길어진다.
2. **단어 단위**: 공백이나 형태소 기준으로 단어를 사용한다. 효율적이지만 신조어와 오탈자에 약하다.
3. **서브워드 단위**: 자주 등장하는 문자열 조각을 조합한다. BPE, WordPiece, Unigram이 대표적이며 현대 언어 모델에서 널리 사용된다.

어휘 사전에는 일반 토큰 외에 특수 토큰도 포함된다. `[PAD]`는 배치 길이 맞춤, `[UNK]`는 알 수 없는 토큰, `[BOS]`와 `[EOS]`는 문장 시작과 종료를 나타낸다. 토크나이저가 같은 문장을 항상 같은 ID 시퀀스로 변환해야 학습과 추론이 일관된다.

한국어는 조사와 어미가 결합하고 띄어쓰기가 다양하므로 단순한 공백 토큰화만으로는 한계가 있다. 서브워드 토큰화는 `"개발자입니다"`를 여러 조각으로 분해해 미등록 단어 문제를 줄인다. 다만 토큰 수가 늘어나면 메모리 사용량과 추론 시간이 증가한다. 따라서 모델의 최대 컨텍스트 길이와 언어별 토큰 효율을 함께 확인해야 한다.

## 코드 예제

```python
from collections import Counter

text = "나는 개발자다 나는 파이썬 개발자다"
tokens = text.split()

# 학습: 빈도 기반으로 어휘 사전 생성
vocab = {"[PAD]": 0, "[UNK]": 1}
for token, _ in Counter(tokens).most_common():
    vocab.setdefault(token, len(vocab))

# 인코딩과 디코딩
ids = [vocab.get(token, vocab["[UNK]"]) for token in tokens]
id_to_token = {i: t for t, i in vocab.items()}
decoded = " ".join(id_to_token[i] for i in ids)

print(vocab)   # {'[PAD]': 0, '[UNK]': 1, ...}
print(ids)     # [2, 3, 2, 4, 3, 5]
print(decoded) # 나는 개발자다 나는 파이썬 개발자다
```

실무에서는 직접 구현한 단순 사전보다 Hugging Face의 `AutoTokenizer`를 사용한다. 모델과 토크나이저가 다르면 동일한 텍스트도 다른 ID로 변환될 수 있으므로 반드시 한 쌍으로 관리해야 한다.

## 면접 질문

### 1. 단어 단위 토큰화보다 서브워드 토큰화가 널리 사용되는 이유는?

단어 단위는 어휘 사전이 커지고 새로운 단어가 등장하면 `[UNK]`가 발생한다. 서브워드는 단어를 작은 조각으로 분해해 미등록 단어를 줄이면서 어휘 크기도 관리할 수 있다.

### 2. 토큰 수가 중요한 이유는?

모델의 최대 컨텍스트 길이와 계산량이 토큰 수에 의해 결정되기 때문이다. 같은 문장이라도 토큰화 방식에 따라 비용과 처리 가능한 문맥 길이가 달라진다.

## 한 줄 정리

토큰화는 텍스트를 모델 입력으로 바꾸는 규칙이며, 어휘 사전은 그 토큰을 정수 ID로 연결하는 핵심 데이터 구조다.
