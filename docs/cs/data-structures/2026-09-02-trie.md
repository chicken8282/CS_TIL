# Trie(트라이): 문자열 검색의 기본과 실수 방지

- 문자열을 공통 접두사 기준으로 저장해 검색·자동완성에 유리하다.
- 삽입과 검색 시간은 문자열 길이를 `L`이라 할 때 `O(L)`이다.
- `is_end` 표시 누락, 자식 노드 관리 방식 선택 오류, 삭제 로직 실수가 가장 흔하다.

## 개념 설명

Trie는 문자열을 문자 단위의 경로로 표현하는 트리 자료구조다. 예를 들어 `car`, `cat`은 `c → a`까지 경로를 공유하고, 이후 `r`, `t`로 갈라진다. 따라서 문자열 개수가 많아도 검색 시간은 전체 문자열 개수보다 검색어 길이에 주로 영향을 받는다.

각 노드는 자식 문자와 단어 종료 여부(`is_end`)를 가진다. `car`가 저장된 뒤 `ca`를 검색했을 때 실패해야 하므로, 노드가 존재하는 것과 단어가 완성된 것은 반드시 구분해야 한다. 이것이 가장 흔한 실수다.

문자열의 길이가 `L`일 때 삽입·검색은 `O(L)`, 삭제도 일반적으로 `O(L)`이다. 공간 복잡도는 최악의 경우 저장된 모든 문자의 합에 비례한다. 배열 자식 테이블은 빠르지만 문자 집합이 작고 고정일 때 적합하다. 영어 소문자처럼 범위가 명확하지 않다면 해시맵을 사용해 메모리 낭비를 줄일 수 있다.

자주 하는 실수는 다음과 같다.

- 마지막 노드에 `is_end=True`를 설정하지 않아 접두사를 단어로 잘못 판단한다.
- 검색 시 중간 노드만 존재하면 성공으로 처리한다.
- 삭제할 때 공유 접두사 노드까지 제거해 다른 단어를 망가뜨린다.
- 모든 노드에 26칸 배열을 무조건 할당해 희소한 데이터에서 메모리를 낭비한다.
- 자동완성 결과를 DFS로 수집하면서 방문 순서와 정렬 조건을 고려하지 않는다.
- 대소문자, 유니코드, 빈 문자열 정책을 입력 전에 정하지 않는다.

삭제는 먼저 단어 종료 표시를 해제하고, 자식이 없을 때만 부모에서 해당 노드를 제거해야 한다. 단순히 검색된 경로 전체를 지우는 구현은 `car`와 `cat`이 함께 있을 때 `car` 삭제 후 `cat`까지 손상시키는 안티패턴이다.

## 코드 예시

```python
class Node:
    def __init__(self):
        self.child = {}
        self.end = False

class Trie:
    def __init__(self):
        self.root = Node()

    def insert(self, word):
        cur = self.root
        for ch in word:
            cur = cur.child.setdefault(ch, Node())
        cur.end = True

    def search(self, word):
        cur = self.root
        for ch in word:
            if ch not in cur.child:
                return False
            cur = cur.child[ch]
        return cur.end
```

## 면접 질문

### 1. HashMap으로 문자열을 저장하는 것과 Trie의 차이는?

HashMap은 문자열 전체를 키로 사용해 평균 `O(1)` 검색이 가능하지만 접두사 검색과 자동완성이 비효율적이다. Trie는 `O(L)`로 접두사 경로를 바로 탐색할 수 있다.

### 2. Trie가 항상 최선의 자료구조인가?

아니다. 문자열 수가 적거나 접두사 검색이 필요 없으면 정렬 배열, HashSet, 정렬된 벡터가 더 단순하고 메모리 효율적일 수 있다. Trie는 메모리 사용량과 구현 복잡성을 감수하고 빠른 접두사 연산이 필요할 때 적합하다.

> **한 줄 요약:** Trie는 접두사를 공유해 문자열 검색을 빠르게 하지만, `is_end`와 공유 노드 삭제를 잘못 처리하면 정확성과 데이터 무결성이 깨진다.
